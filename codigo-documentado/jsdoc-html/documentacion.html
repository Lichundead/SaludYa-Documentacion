Documentación generada con JSDoc de los módulos del servidor (server.js, database.js, swagger.js). El backend implementa una API REST con Node.js + Express y persiste los datos en SQLite mediante better-sqlite3.

module

server

codigo-documentado/server.js

Punto de entrada de la API REST de SaludYa. Configura el servidor Express, el middleware (CORS, JSON), la documentación Swagger y registra los endpoints de autenticación, usuarios y citas.

middleware

cors()

Permite peticiones entre dominios desde el frontend local (http://localhost:3000) y desde el despliegue de Vercel (https://salud-ya-cicd.vercel.app).

app.use( cors({ origin: ["http://localhost:3000", "https://salud-ya-cicd.vercel.app"], credentials: true, }) );
function

loginHandler(req, res)

Autentica a un usuario validando su correo y contraseña contra la tabla usuarios. Registrado en POST /login.

Parámetros

NombreTipoDescripción
req express.Request req.body debe contener email (string) y password (string).
res express.Response Respuesta HTTP en formato JSON.

Retorna

void — { success: true, user } si las credenciales son válidas; { success: false } si no coinciden o si ocurre un error 500.
/** POST /login */ app.post("/login", (req, res) => { const { email, password } = req.body; const user = db .prepare(`SELECT * FROM usuarios WHERE email = ? AND password = ?`) .get(email, password); if (user) return res.json({ success: true, user }); res.json({ success: false }); });
function

registerHandler(req, res)

Registra un nuevo usuario en la tabla usuarios. El correo electrónico debe ser único; si ya existe, devuelve { success: false }. Registrado en POST /register.

Parámetros

NombreTipoDescripción
req express.Request req.body con los campos del usuario: nombre, email, password, telefono, tipo_id, numero_id, rh. Los tres primeros son obligatorios.
res express.Response Respuesta HTTP en formato JSON.

Retorna

void — { success: true, id } con el lastInsertRowid del registro creado; { success: false } si el correo ya existe u ocurre otro error.
/** POST /register */ app.post("/register", (req, res) => { const { nombre, email, password, telefono, tipo_id, numero_id, rh } = req.body; const result = db .prepare(`INSERT INTO usuarios (nombre, email, password, telefono, tipo_id, numero_id, rh) VALUES (?, ?, ?, ?, ?, ?, ?)`) .run(nombre, email, password, telefono, tipo_id, numero_id, rh); res.json({ success: true, id: result.lastInsertRowid }); });
function

getUsuarioHandler(req, res)

Obtiene los datos de un usuario a partir de su correo electrónico. Registrado en GET /usuario/:email.

Parámetros

NombreTipoDescripción
req express.Request req.params.email — correo del usuario a buscar.
res express.Response Respuesta HTTP en formato JSON.

Retorna

void — { success: true, user } con el objeto del usuario (o undefined si no existe en la BD); { success: false } ante error.
/** GET /usuario/:email */ app.get("/usuario/:email", (req, res) => { const user = db .prepare(`SELECT * FROM usuarios WHERE email = ?`) .get(req.params.email); res.json({ success: true, user }); });
function

crearCitaHandler(req, res)

Crea una nueva cita médica en la tabla citas. Registrado en POST /citas.

Parámetros

NombreTipoDescripción
req express.Request req.body con: paciente_email, especialidad, medico, fecha (YYYY-MM-DD), hora (HH:MM). Todos obligatorios.
res express.Response Respuesta HTTP en formato JSON.

Retorna

void — { success: true, id } con el lastInsertRowid de la cita; { success: false } ante error.
/** POST /citas */ app.post("/citas", (req, res) => { const { paciente_email, especialidad, medico, fecha, hora } = req.body; const result = db .prepare(`INSERT INTO citas (paciente_email, especialidad, medico, fecha, hora) VALUES (?, ?, ?, ?, ?)`) .run(paciente_email, especialidad, medico, fecha, hora); res.json({ success: true, id: result.lastInsertRowid }); });
function

getCitasHandler(req, res)

Obtiene todas las citas asociadas al correo de un paciente. Registrado en GET /citas/:email.

Parámetros

NombreTipoDescripción
req express.Request req.params.email — correo del paciente.
res express.Response Respuesta HTTP en formato JSON.

Retorna

void — { success: true, citas } con el arreglo de citas (vacío si no hay); { success: false } ante error.
/** GET /citas/:email */ app.get("/citas/:email", (req, res) => { const citas = db .prepare(`SELECT * FROM citas WHERE paciente_email = ?`) .all(req.params.email); res.json({ success: true, citas }); });
constant

PORT

Puerto en el que escucha el servidor. En producción, Render inyecta process.env.PORT; en desarrollo local se usa 3001.

Tipo

number
const PORT = process.env.PORT || 3001;
module

database

codigo-documentado/database.js

Inicializa la base de datos SQLite de SaludYa mediante better-sqlite3. Crea las tablas usuarios y citas si no existen e inserta usuarios de demostración. Exporta la instancia de conexión para ser usada por la API.

constant

db

Instancia de conexión a la base de datos SQLite. El archivo saludya.db se crea automáticamente en el primer arranque del backend, en el directorio raíz del servicio.

Tipo

Database (better-sqlite3)
const Database = require("better-sqlite3"); const db = new Database("./saludya.db");

module

swagger

codigo-documentado/swagger.js

Configuración de la documentación OpenAPI 3.0 de la API de SaludYa. Usa swagger-jsdoc para generar la especificación a partir de las anotaciones @openapi escritas en los comentarios de server.js. La especificación resultante es consumida por swagger-ui-express en la ruta /api-docs.

constant

options

Opciones de configuración para swagger-jsdoc. Define la información de la API (título, versión, descripción, contacto, licencia), los servidores y los esquemas de los modelos de datos (Usuario y Cita).

Tipo

object

Propiedad definition.servers

constant

swaggerSpec

Especificación OpenAPI 3.0 generada a partir de las anotaciones @openapi de server.js y la configuración del objeto options. Es el valor exportado por este módulo y pasado a swaggerUi.setup() en server.js.

Tipo

object
const swaggerSpec = swaggerJSDoc(options); module.exports = swaggerSpec;
